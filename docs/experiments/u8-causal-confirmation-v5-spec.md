## Changes from v4

All 81,900 exposed v4 semantic groups are Development Corpus under SHA-256 `0eae44e4ca7a2ba050f02ab87c0e2de27fecde457d8744636e29afdd6d404787` and are excluded from v5 alongside the complete v1, v2, and v3 audit corpora.

The defect was confined to recovery validation. Campaigns contain 8,190 roots, so the 4,096-entry active-knowledge cap legitimately prevents a new Knowledge Revision from being promoted. The unchanged champion summarized the pre-Campaign Experience prefix, while recovery incorrectly required it to summarize the complete later ledger. Knowledge Revisions now encode an exact Experience-ledger attempt watermark, and recovery validates each immutable revision against that prefix. Validation also accepts any matching verified parent derivation rather than one arbitrary equivalent parent. An explicit release-mode regression gate trains the full stack, evaluates one complete 8,190-Seed consumed-v4 Campaign, and successfully reopens the resulting Derived-Operator bundle. The post-fix v7 Bootstrap baseline completed 96 of 96 assignments with no failure or Protocol Deviation; v5 pins its report file SHA-256 `b8a5e2c8ef87a88c4576d934e8d9e234961942cc599973d789a5fe4e29ad6daa`.

No search policy, treatment, Resource Envelope, outcome, practical threshold, uncertainty method, multiplicity rule, or stopping rule changed after observing v4. ## Claim

Under equal evaluation Resource Envelopes, shared and consolidated Reflex improves previously unseen unary `u8` semantic Campaigns more effectively than isolated Bootstrap. The paired full-versus-Bootstrap contrast tests the complete shared cross-Seed stack. One-factor ablations separately test the learned Model Revision and Derived Operators.

## Development and semantic split

Training uses only 192 declared XOR Seeds: 96 refuted `xor(input, c)` Seeds for `c = 1..96`, followed by 96 useful `xor(xor(xor(input, c), 0), 0)` Seeds for `c = 97..192`. The training session has a 100,000-request verifier envelope.

Development data additionally contains the 8,190-case exploratory pilot and every semantic group exposed by v1 through v4. The pilot generator enumerates `c1 = 1..255`, `r = 1..7`, and `c2 = 1..255` lexicographically. Its base is `rotl(add(rotl(add(input,c1),r),c2),r)` and surface categories cycle by ordinal through `xor(base,31)`, `xor(base,0)`, and `xor(xor(base,0),0)`.

Each v5 audit record is generated by `SHA-256(seed || counter.to_le_bytes())`. Digest bytes determine `c1`, `r1`, `c2`, and `r2`; accepted-record ordinals cycle through the same three surface categories. Rejection sampling excludes every XOR group, every pilot group, every consumed v1/v2/v3/v4 audit group, and every v5 group accepted by an earlier replicate.

Training and both ablation bundles are built and validated through normal Runtime import before audit generation. Development code never generates or observes sealed v5 records.

## Treatments and envelopes

Each of ten paired Campaign replicates has 8,190 v5 audit Seeds. Treatment order is the replicate-index cyclic rotation of:

1. `full`: the trained shared Domain Bundle.
2. `no-model`: the same bundle with its Learning state and Model Revision ID replaced by those from a production-created Bootstrap bundle.
3. `no-derived`: the same bundle with Derived Operators removed and its canonical Knowledge Revision ID recomputed.
4. `bootstrap`: a fresh isolated production Runtime.

Every evaluation uses public `improve` in its own process with one worker, 256 MiB resident memory, 256 MiB durable storage, 60 seconds elapsed time, 60 seconds CPU time, and exactly 10,500 total verifier requests. A 120-second outer watchdog retains a timeout as a failed assignment. Import replay, evaluation-time learning, adaptation, and consolidation all count inside the treatment envelope. Every treatment starts from fixed pre-audit state, and post-audit bundles are discarded after recovery validation.

## Outcomes and decision rule

The Primary Outcome is the paired difference in aggregate node count across exactly the 8,190 final Pareto Artifacts whose origin is a v5 audit Seed. Lower is better. Development-origin Artifacts are excluded. Protected aggregates are depth, encoded bytes, and evaluator operations. Peak live temporaries and environment-pinned evaluation nanoseconds are diagnostics.

Practical thresholds for `other - full` remain 500 nodes for Bootstrap, 250 for the Model ablation, and 200 for the Derived Operator ablation.

For each contrast, 10,000 paired bootstrap resamples use the content-addressed index stream declared in the executable specification. One-sided percentile lower bounds use Bonferroni `alpha = 0.01 / 3`, giving 99% family-wise confidence. Confirmation requires every paired effect to be positive, every adjusted lower bound to meet its threshold, and `full` never to regress against its paired comparator on any protected aggregate. Missing, crashed, timed-out, malformed, or otherwise deviating assignments prevent confirmation. There is no outcome-dependent stopping or exclusion.

Observer-sequence anytime traces record v5 audit-origin Pareto aggregates at sequence 1, every 256th sequence, and the final sequence. The report retains every assignment, raw output, exact audit record, Resource Usage, environment, revision and bundle hashes, per-Artifact Pareto results, paired distributions, adjusted bounds, Protocol Deviations, and a content digest.

After every assignment, completed recovery independently replays retained Artifacts through the exhaustive Verification Kernel under a trivially satisfied Success Condition. Recovery must complete as `SuccessConditionsSatisfied` with an identical v5 audit Artifact count, deterministic aggregate Measurements, and Artifact-key digest.
