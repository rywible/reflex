# Unary `u8` causal confirmation v1

Status: frozen before audit exposure

Experiment Specification SHA-256: `543bf37e7524f9a19ae805fb86530f2f1b0230a5a39e5e57a1c2f4fc7ba3a112`

This is the human-readable registration for the immutable specification encoded by `xtask/src/causal.rs`. The executable checks the canonical JSON digest above before it can generate an audit corpus. The implementation and this registration are committed together before confirmation.

## Claim

Under equal evaluation Resource Envelopes, shared and consolidated Reflex improves previously unseen unary `u8` semantic Campaigns more effectively than isolated Bootstrap. One-factor ablations separately test the learned Model Revision and Derived Operators.

The domain Semantic Identity is `reflex-bitvec/u8/unary/xor-add-rotl/v2`. Each correctness group is identified by SHA-256 over `reflex-u8-semantic-function-v1\0` followed by the expression's exhaustive outputs for inputs 0 through 255.

## Development and semantic split

Training uses only 192 declared XOR Seeds: 96 refuted `xor(input, c)` Seeds for `c = 1..96`, followed by 96 useful `xor(xor(xor(input, c), 0), 0)` Seeds for `c = 97..192`. The training session has a 100,000-request verifier envelope.

The Development Corpus also contains the 8,190-case exploratory pilot. Its generator enumerates `c1 = 1..255`, `r = 1..7`, and `c2 = 1..255` lexicographically. Its base is `rotl(add(rotl(add(input,c1),r),c2),r)` and surface categories cycle by ordinal through `xor(base,31)`, `xor(base,0)`, and `xor(xor(base,0),0)`.

Each audit record is generated by `SHA-256(seed || counter.to_le_bytes())`. Digest bytes determine `c1`, `r1`, `c2`, and `r2`; the accepted-record ordinal cycles through the same three surface categories, with independent rotations in the audit base. Rejection sampling excludes every XOR semantic group, every pilot semantic group, and every audit group accepted by an earlier replicate. All ten 64-hex-digit seeds are part of the content-addressed executable specification and will be published with every accepted audit record after unsealing.

Training and both ablation bundles are built and validated through normal Runtime import before audit generation begins. Development code never generates or observes the sealed audit records.

## Treatments and envelopes

Each of ten paired Campaign replicates has 8,190 audit Seeds. Treatment order is the replicate-index cyclic rotation of:

1. `full`: the trained shared Domain Bundle.
2. `no-model`: the same bundle with its Learning state and Model Revision ID replaced by those from a production-created Bootstrap bundle.
3. `no-derived`: the same bundle with Derived Operators removed and its canonical Knowledge Revision ID recomputed.
4. `bootstrap`: a fresh isolated production Runtime.

Every evaluation uses the public `improve` interface in its own process with one worker, 256 MiB resident memory, 256 MiB durable storage, 60 seconds elapsed time, 60 seconds CPU time, and exactly 10,500 total verifier requests. A 120-second outer watchdog retains a timeout as a failed assignment. Import replay, evaluation-time learning, adaptation, and consolidation all count inside the treatment envelope. Post-audit bundles are discarded.

## Outcomes and decision rule

The Primary Outcome is the paired difference in aggregate node count across exactly the 8,190 final Pareto Artifacts whose origin is an audit Seed. Lower is better. Training-origin Artifacts are excluded. Protected aggregate outcomes are depth, encoded bytes, and evaluator operations.

The practical thresholds for `other - full` are:

- Bootstrap: 500 nodes
- Model ablation: 250 nodes
- Derived Operator ablation: 200 nodes

For each contrast, 10,000 paired bootstrap resamples use the content-addressed index stream declared in the executable specification. One-sided percentile lower bounds use Bonferroni `alpha = 0.01 / 3`, giving 99% family-wise confidence. Confirmation requires every paired effect to be positive, every adjusted lower bound to meet its threshold, and `full` never to regress against its paired comparator on any protected aggregate. Missing, crashed, timed-out, malformed, or otherwise deviating assignments prevent confirmation. There is no outcome-dependent stopping or exclusion.

Observer-sequence anytime traces record audit-origin Pareto aggregates at sequence 1, every 256th sequence, and the final sequence. The report retains all assignments, raw stdout and stderr, exact audit records, Resource Usage, environment, revision IDs, bundle and Artifact-set hashes, paired distributions, adjusted bounds, Protocol Deviations, and a content digest.

After every assignment, completed bundle recovery independently replays retained Artifacts through the exhaustive Verification Kernel. Recovery must stop at the initial observer delivery with an identical audit Artifact count, aggregate Measurements, and Artifact-key digest.
