# Index domain premises before bounded enumeration

Lean's proof-substitution Operator enumerates supporting library Artifacts through one immutable in-memory retrieval index built with the Domain Definition. Exact proposition matches remain the first tier. Remaining donors are ordered by deterministic, symbol-independent proposition-shape overlap with document-frequency weighting; common tokens are omitted, structural-size distance breaks relevance ties, and original corpus order is the final tie-breaker and completeness fallback. Contiguous sparse postings are merged by one bounded cursor per query token into a top-k heap, so every structurally matching donor is scored while reusable query workspace scales with the Candidate window instead of the library. Exact/proof identity uses fixed SHA-256 keys rather than cloned expression trees, retained structures are contiguous vectors with capacity-based accounting, and decoded Artifact storage is charged at a conservative multiple of its canonical bytes. The retained index and per-lane worst-case scratch are charged through the Operator interface before search begins. The index changes only which legal proposals enter a bounded generation window. It never establishes correctness, uses no learned state or Optimization Goal, and every emitted Candidate still passes through the official Lean kernel.

Each supported Candidate records Proposal Provenance as the SHA-256 of the donor's canonical Artifact encoding. Proposal Features record the retrieval tier, relevance, boundary margin, emitted rank, and signed structural differences from the Seed rather than the donor's original corpus position. Both survive through every Candidate Fate and verified attempt in Experience for causal attribution, but neither is Verification evidence. Because enumeration order and learned feature values change, the Lean Semantic Identity advances from `reflex-lean-v3` to `reflex-lean-v4`; prior Lean Bundles require Semantic Migration rather than silent reuse. The durable Experience and recovery framing also advances the global Runtime revision from 10 to 11, so every older Bundle is explicitly incompatible. The retrieval index and its reusable scratch remain private to `reflex-lean`; the only shared-interface additions are domain-independent Operator resource accounting and Proposal Provenance, which apply equally to non-premise domains.

## Considered options

Scanning the full library in stored order is cheap but lets unrelated early donors consume the finite generation window before relevant premises reach the Runtime. Recomputing every structural sketch per query avoids retained postings but is substantially slower on CPU. Learned embeddings or declaration-name features would add model and vocabulary cost before the verified evidence supports it, and proof-size ordering would improperly smuggle one possible Optimization Goal into domain enumeration.
