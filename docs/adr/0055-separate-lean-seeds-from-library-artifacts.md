# Separate Lean Seeds from library Artifacts

A Lean Domain corpus distinguishes Seed entries from already Verified library Artifacts available to Primitive Operators. A convenience constructor may deliberately install the same theorem set in both roles, but experiments and consumers can provide the roles independently. Corpus membership is operational input, not part of the Domain's Semantic Identity, so a compatible Domain Bundle can resume against a new Seed Scope while retaining its replayed knowledge.

## Consequences

Training cannot observe held-out proof bodies merely because the later evaluation Seeds share a process-level corpus. Held-out Seeds are not automatically available as substitutions for one another. Full and counterfactual treatments receive the same explicit library Artifacts; their differences come from retained Knowledge and Model Revisions rather than unequal access to existing proofs.

The primary Lean optimizer Development stratum uses human-facing declarations with bounded proof size and at least one independently named, same-statement library Artifact. Generated declaration components and very large proofs remain reportable outlier strata for later frozen experiments rather than silently contaminating the fast primary diagnostic.
