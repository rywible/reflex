# Allocate typed Investments through Model Ecologies

A complete Model Revision is a Model Ecology of a permanent Bootstrap Revision, routed Specialist Revisions, calibration, and competence metadata. Its members forecast typed outcomes and resource demands for heterogeneous Investments rather than voting on Candidates or optimizing one reward scalar; the deterministic Runtime Controller applies caller Preferences, Pareto comparison, correlation, Protected Allocations, and hard Resource Envelopes before execution.

## Considered Options

One larger model would make inference and promotion simpler but would force unrelated proof construction, Verification cost, repair, Potential, and consolidation judgments into one capacity and one global champion. A public model registry would permit more components while leaking orchestration to consumers and Domain Definitions.

## Consequences

Inference must route each opportunity to a bounded relevant subset so retained specialists do not make hot-path cost proportional to ecology size. Split, merge, distillation, retention, retirement, promotion, and rollback replace one complete immutable ecology atomically; shared evidence lineage prevents correlated specialists from masquerading as independent confidence.

The Model Ecology component authenticated by `IntelligenceCore` is the sole current Model Revision authority. Current restart bundles do not retain a parallel online learner or model payload. Completed legacy FTRL state is accepted only through a one-time import into an initial generalist Specialist and is then discarded.

Every selected operational action performs bounded work before it may settle as Completed. Generation and exploration enumerate the selected Operator; Repair replays the exact retained Refuted Candidate and its Rejection Advisory inside a bounded local neighborhood and is offered only while that Candidate's verified parent is on the active Search Frontier; training prepares the selected Specialist mandate; comparison evaluates a concrete prepared revision; consolidation selects a concrete compiler strategy; shadow execution opens a paired campaign; and policy proposal materializes the exact challenger selected by allocation. Receipts are carried through generated Candidates, Verification Experience, and mechanically induced downstream consequences so action value is attributable after restart rather than inferred from aggregate success.

Operational publication is a progress transaction, not a receipt append. The transaction retains the exact generated Candidate prefix and advances only the enumeration progress represented by that prefix. The live epoch continues from the same staged progress, including its Derived-Operator window, and a later time, memory, verification, or durability refusal cannot roll back Candidates that a Completed action already made restart-reachable. Every such Candidate must therefore remain available after restart until it receives a terminal fate.

When standard and exploratory training plans coexist, the Runtime reserves their exact simultaneous residency before preparing either. The market may defer both, select one, or select both under the remaining Resource Envelope; a receipt-only pseudo-plan is not a completed training action.
